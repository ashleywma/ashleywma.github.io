EECS 482 (Operating Systems)

University of Michigan · Fall 2025

A project-driven systems course covering concurrency, scheduling, virtual memory, and file systems. Across three C++ projects, I implemented the operating-system abstractions behind threads, memory, and persistent storage. Each project was built with a team of three.

Implementation source is private to respect course policies; these are high-level descriptions of the systems and concepts.

Concurrency

Threads, mutexes, condition variables, interrupts, scheduling, and synchronization across multiple CPUs.

Memory

Page tables, faults, swap- and file-backed pages, clock eviction, sharing, and copy-on-write.

Storage

Inodes, directories, block allocation, ownership checks, network requests, and fine-grained locking.

Projects

Project 1 — User-level thread library

A user-level thread runtime implementing thread creation, yielding, joining, mutexes, and condition variables on top of low-level execution contexts. The library manages thread stacks and context switching, schedules runnable work across multiple simulated CPUs, and safely reclaims completed threads. Timer interrupts provide preemptive scheduling, while inter-processor interrupts wake suspended CPUs when new work becomes available. The implementation coordinates ready, running, waiting, and completed threads while preventing lost wakeups and protecting scheduler state during asynchronous interrupts.

Project 2 — Virtual-memory pager

An external pager that manages per-process virtual address spaces, handles page faults, and moves data between physical memory, swap, and files. It supports both swap-backed and file-backed mappings, shares file-backed physical pages across processes, and uses a clock-based replacement policy driven by reference and dirty state. Forked processes share swap-backed pages through copy-on-write, including a pinned zero-page optimization for newly mapped memory, while eager swap reservation guarantees that private copies can be created later. Page-table permissions are updated dynamically to track access and trigger the faults needed for eviction, writeback, and deferred copying.

Project 3 — Concurrent network file server

A multithreaded network file server supporting authenticated create, delete, read, and write requests over TCP. The server parses and validates requests, traverses inode-backed directory trees, enforces file ownership, manages directory entries, and allocates disk blocks. At startup, it reconstructs free-space metadata by scanning the existing file system. Fine-grained per-inode reader and upgradeable locks allow unrelated paths and read-only operations to proceed concurrently, with mutations taking exclusive access only where required. Shared metadata, including the free-block pool, is synchronized independently to preserve concurrency across otherwise unrelated requests.
